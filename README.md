# Server Manager

**Server Manager** — панель управления, предназначенная для запуска и управления различными проектами на сервере. С её помощью можно работать с разными типами проектов, включая Minecraft-серверы, Node.js-приложения и другие исполняемые файлы.

Работает в Windows и Linux. Написана на Node.js.

## 📌 О проекте

Этот проект создан исключительно с помощью искусственного интеллекта (ИИ).

Я не рассчитываю на какую-либо популярность, прибыль или особое внимание к проекту. Он создавался для личных целей и экспериментов.

При этом я не против, если кто-то захочет воспользоваться панелью для своих задач. Если проект окажется кому-то полезен — значит, он создан не зря!

## ⚙️ Подключение серверов

Для работы панели необходимо запустить её на сервере, где находятся файлы, с которыми вы хотите работать.

### 🖥️ Если у вас один сервер

Просто запустите панель на том сервере, где находятся ваши проекты и файлы.

### 🌐 Если у вас два или более серверов

1. Запустите панель на каждом сервере, которым хотите управлять.
2. Откройте категорию **«Серверы»** в панели управления.
3. Подключите остальные серверы, следуя инструкциям в интерфейсе.
   1. Все необходимые данные для подключения отображаются в терминале соответствующего сервера.

После подключения вы сможете управлять проектами на разных серверах через предусмотренную системой интеграцию.

## 💡 Возможности проекта

- Запуск и остановка различных проектов.
- Управление файлами и хранилищем сервера.
- Работа с несколькими серверами.
- Централизованное управление проектами через веб-интерфейс.

Доступные возможности зависят от текущей версии панели.

## 1. Установка

### Что нужно установить

| Что | Зачем | Где взять |
|---|---|---|
| **Node.js 20 или новее** | запускает саму панель | <https://nodejs.org> (версия LTS) |
| Java, Python, .NET, Docker | только если запускаете такие приложения (например, Minecraft — Java) | на сайтах производителей |
| 7-Zip или unrar | только для распаковки `.rar`, `.7z` и редких архивов (ZIP и TAR работают без них) | <https://www.7-zip.org> |

Проверьте Node.js: откройте терминал (в Windows — PowerShell) и выполните `node -v` — должно быть `v20` или больше.

### Шаги

1. Распакуйте архив проекта в удобную папку, например `C:\ServerManager` или `/opt/server-manager`.
2. В терминале перейдите в эту папку и установите зависимости:

   ```
   cd C:\ServerManager
   npm install
   ```

3. Запустите панель (см. раздел 2).

> Для обновления существующей установки читайте раздел 9 — **не** копируйте проект поверх рабочей папки без резервной копии.

## 2. Запуск

```
npm start
```

В консоли появится адрес, например `http://127.0.0.1:3000`. Откройте его в браузере.

**Первый вход:** логин `admin`, пароль `admin`. Сразу откройте «Настройки» и смените пароль — до смены панель показывает жёлтое предупреждение.

По умолчанию панель слушает **только этот компьютер** (`"host": "127.0.0.1"`). Чтобы открывать её с других компьютеров, поставьте в `config.json` `"host": "0.0.0.0"` и обязательно смените пароль администратора. Для доступа через интернет используйте HTTPS (пример настройки nginx — `docs/nginx.conf.example`).

### Запуск как служба

**Linux (systemd).** Создайте отдельного пользователя без прав root и установите службу:

```
sudo useradd --system --home /opt/server-manager servermanager
sudo chown -R servermanager /opt/server-manager
sed -e "s|__USER__|servermanager|" -e "s|__DIR__|/opt/server-manager|" -e "s|__NODE__|$(which node)|" \
    server-manager.service | sudo tee /etc/systemd/system/server-manager.service
sudo systemctl daemon-reload
sudo systemctl enable --now server-manager
```

Остановка службы останавливает и запущенные ею приложения. Журнал службы: `journalctl -u server-manager -f`.

**Windows.** Самый простой способ — Планировщик заданий: «Создать задачу» → триггер «При запуске компьютера» → действие «Запуск программы» `node.exe`, аргумент `server.js`, «Рабочая папка» — папка проекта. Либо используйте NSSM/WinSW.

## 4. Настройки (`config.json`)

Если какого-то параметра в файле нет, используется значение по умолчанию — старый `config.json` продолжает работать.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `port` | `80` | порт панели |
| `host` | `127.0.0.1` | `127.0.0.1` — только этот компьютер; `0.0.0.0` — доступна по сети |
| `fileRoot` | `./servers` | «Хранилище проектов» — корневая папка раздела «Файлы» |
| `backupRoot`, `logRoot`, `uploadRoot` | `./storage/…` | где хранятся копии, логи и данные загрузок |
| `trustProxy` | `0` | поставьте `1`, если панель стоит за nginx — тогда в журнале и при защите от подбора пароля будут настоящие адреса |
| `allowExternalLinks` | `false` | разрешить символьные ссылки, ведущие за пределы выбранной папки (**небезопасно**, лучше не включать) |
| `jwtSecret` | создаётся сам | секрет подписи входа. Не показывайте и не публикуйте |
| `agent`, `agentToken`, `agentId`, `agentOnly`, `announce`, `discovery` | — | настройки режима «агент» (см. раздел 8) |
| `maxExtractMb`, `maxExtractGb`, `maxExtractFiles` | как раньше | ограничения распаковки (защита от «архивных бомб») |
| `limits`, `timeouts` | см. ниже | лимиты и таймауты передачи файлов |

### Лимиты и таймауты

```json
"limits": {
  "maxFileGb": 500,          // максимальный размер одного файла
  "uploadChunkMb": 16,       // размер одной части при загрузке (1…64 МБ)
  "minFreeDiskMb": 256,      // сколько места должно остаться на диске после загрузки
  "uploadSessionHours": 48,  // сколько хранить недозагруженный файл для продолжения
  "maxActiveUploads": 8,     // одновременных незавершённых загрузок у одного пользователя
  "maxZipItems": 2000        // максимум элементов в одном ZIP-скачивании
},
"timeouts": {
  "requestMinutes": 20,      // максимум времени на получение ОДНОГО запроса (одной части файла)
  "idleMinutes": 20,         // соединение, по которому 20 минут не идут данные, закрывается
  "headersSeconds": 60,      // время на заголовки запроса
  "keepAliveSeconds": 65,    // сколько держать свободное соединение
  "uploadStallSeconds": 60,  // загрузка «зависла»: данные перестали приходить
  "proxyIdleMinutes": 20     // сколько главная панель ждёт молчащий удалённый сервер
}
```

(В настоящем `config.json` комментарии `//` писать нельзя — это только пояснение. Готовый файл без комментариев — `config.example.json`.)

**Как это работает.** Файл не загружается одним запросом. Браузер делит его на части (по умолчанию 16 МБ) и отправляет по очереди; сервер пишет каждую часть прямо на диск, не держа файл в памяти. Поэтому:

- лимит 500 ГБ не требует 500 ГБ памяти — расходуется только место на диске;
- ни один запрос не длится дольше нескольких секунд-минут, а «20 минут» — страховка от зависания, а не время передачи;
- при обрыве связи повторяется только последняя часть, а если закрыть страницу — загрузку можно продолжить, выбрав тот же файл снова;
- старый файл заменяется новым только после полной загрузки, одним мгновенным переименованием.

Старый параметр `maxUploadMb` больше не используется — лимит задаётся `limits.maxFileGb`.

**Что нужно настроить отдельно (вне панели).**

- *nginx / другой прокси перед панелью:* `client_max_body_size` не меньше размера части (например `100m`), `proxy_request_buffering off`, `proxy_buffering off`, `proxy_read_timeout`/`proxy_send_timeout` — `1200s`. Готовый пример — `docs/nginx.conf.example`. **Не** ставьте `client_max_body_size 500g`: так не нужно, файл идёт частями.
- *Диск:* в файловой системе FAT32 файл больше 4 ГБ создать невозможно (панель сообщит об этом понятной ошибкой), используйте NTFS/ext4/exFAT.
- *Свободное место:* панель проверяет его перед началом загрузки и откажет сразу, если места не хватает.

## 5. Приложения

### Добавить приложение

Нажмите «+ Добавить приложение». Есть два пути:

1. **Конструктор** — выберите тип (Minecraft, Node.js, Python, .NET, EXE/скрипт или «Своя команда»), укажите папку и файл запуска. Панель сама соберёт команду и покажет её.
2. **Из раздела «Файлы»** (самый простой) — см. ниже.

### Кнопка «Использовать проект»

1. Откройте «Файлы» и зайдите в папку со своим проектом (или выберите папку/файл в списке).
2. Нажмите **«🚀 Использовать проект»** (или правая кнопка мыши → «Использовать проект»).
3. Панель **только прочитает** файлы и покажет найденные способы запуска: например, `Java: paper-1.21.4.jar`, `Скрипт: start.sh`, `Node.js: npm start`. У каждого есть оценка («Рекомендуется / Возможно / Маловероятно»), команда, предупреждения (например: «Нужна Java 21, найдена 17», «EULA не принята», «Скрипт содержит опасные команды», «не выполнен npm install»).
4. Выберите вариант и нажмите «Продолжить» — откроется обычная форма создания приложения с уже подставленными папкой и настройками. Проверьте и нажмите «Сохранить».
5. Приложение появится в списке и будет доступно для запуска и остановки. **Ничего не запускается автоматически.**

Если автоопределение не сработало — нажмите «Настроить вручную».

### Запуск, остановка, перезапуск

Кнопки есть на карточке приложения и на его странице. Остановка сначала пробует «вежливый» способ (например, команда `stop` в консоль Minecraft) и только потом завершает процесс принудительно. У приложения можно включить автозапуск, автоперезапуск при падении и зависимости (запускать только после другого приложения).

## 6. Работа с файлами

Раздел «Файлы» работает с настоящей файловой системой. Корень — «Хранилище проектов» (`fileRoot`); пользователь с правом «Доступ к дискам» может выбрать любой диск компьютера.

**Что можно делать**

- Двигаться по папкам: двойной клик, «↑ Вверх», клик по «хлебным крошкам» вверху, Backspace.
- Выделять: клик, Ctrl+клик, Shift+клик, Ctrl+A, галочки; работать сразу с несколькими файлами.
- Создавать папки и файлы, переименовывать (F2), удалять (Delete) — с подтверждением.
- Копировать / вырезать / вставлять (Ctrl+C / X / V или кнопки), переносить файлы перетаскиванием на папку. Копирование идёт в фоне с прогрессом и **отменой**; при ошибке недокопированное удаляется, оригинал не страдает; при перемещении между дисками оригинал удаляется только после проверки.
- Искать по имени во вложенных папках (строка поиска, можно `*` и `?`).
- Сортировать по имени, размеру, дате и типу (клик по заголовку). Режимы «список» и «плитки».
- Загружать: кнопка «Загрузить», «Папка…» или просто **перетащите файлы и папки в окно**.
- Скачивать: один файл, **несколько файлов** или **папку** (они упаковываются в ZIP «на лету» без сжатия — быстро).
- Редактировать текстовые файлы (до 2 МБ). Если файл изменили после открытия, панель предупредит о конфликте.
- Распаковывать архивы (правая кнопка → «Распаковать»).
- Большие папки показываются порциями по 500 элементов («Показать ещё»).

**Очередь передач** (правый нижний угол) показывает для каждой загрузки, скачивания и копирования: прогресс, скорость, объём и оставшееся время, а также кнопки «пауза», «продолжить», «отменить». При обрыве связи загрузка автоматически повторяет попытки.

**Скачивание.** Chrome и Edge (на `https://` или `localhost`) сохраняют файл потоком — с прогрессом в очереди, скоростью и докачкой. В остальных браузерах и для ZIP скачивание ведёт сам браузер (в его списке загрузок).

**Кнопки мыши «назад/вперёд», Alt+←/→** переключают разделы и открытые папки как в обычных сайтах; позиция прокрутки восстанавливается. Адрес можно скопировать: `…/#/files?path=Minecraft/world`.

## 7. Пользователи и права

Откройте «Пользователи» (нужно право «Управление пользователями»).

**Готовые роли**

| Роль | Что может |
|---|---|
| Администратор | всё |
| Оператор | видеть и запускать/останавливать/перезапускать приложения, работать с консолью и логами, работать с файлами (загрузка, скачивание, создание, переименование, удаление, редактирование), делать и восстанавливать резервные копии |
| Только просмотр | видеть панель, список приложений и логи |

**Индивидуальные права.** При создании или изменении пользователя выберите роль, а затем поставьте или снимите галочки — отличия от роли сохранятся как «добавить» и «убрать» (в таблице пользователей они показаны как `+2 −1`). Разрешения со знаком ⚠ позволяют, прямо или косвенно, выполнять код на сервере (создание приложений, редактирование файлов, консоль, Docker и т. п.) — выдавайте их как права администратора.

**Доступ к серверам.** Для каждого пользователя отмечаются серверы, с которыми он может работать («Эта панель» и подключённые компьютеры). Без отметки доступа нет, даже при наличии прав.

**Права проверяет сервер, а не интерфейс.** Скрытая кнопка не защищает: любой запрос без нужного права будет отклонён кодом 403. Это же относится к подключённым компьютерам — панель передаёт им права пользователя, и они проверяют их ещё раз.

**Защита от повышения прав:**

- менять роли и права может только тот, у кого есть «Создание и изменение прав пользователей», и никогда — самому себе;
- выдать можно только те права, которые есть у самого выдающего;
- администраторов создаёт, меняет и удаляет только администратор; последнего администратора удалить или понизить нельзя;
- после смены пароля старые токены входа перестают работать; подбор пароля ограничен (по адресу и по логину).

Полный список разрешений и то, какие запросы им соответствуют, — в `lib/permissions.js` (таблица `ROUTE_RULES`).

## 8. Несколько компьютеров (серверы и агенты)

На втором компьютере установите Server Manager и добавьте в его `config.json`:

```json
{
  "agent": true,
  "agentOnly": true,
 }
```

(`agentOnly` — без интерфейса, только приём команд от главной панели.) При запуске в консоли появится одноразовый **код подключения**. В главной панели: «Серверы» → «+ Добавить сервер» → введите адрес и код (или выберите найденный в сети компьютер). Дальше его можно выбирать в списке слева вверху.

**Обновляйте оба компьютера одновременно.** Главная панель передаёт агенту права пользователя; старый агент их игнорирует и считает все запросы от панели администраторскими (как раньше), поэтому права на нём проверяет только главная панель.

Токен агента хранится в базе главной панели открытым текстом (он нужен для входа на агент): защищайте `server.db` и папку панели.

## 9. Безопасное обновление

1. **Остановите панель.** Остановка также остановит приложения.
2. **Сделайте копию** папки проекта целиком — минимум файлов `server.db`, `config.json` и папок `servers/`, `storage/`.
3. Распакуйте новую версию **в новую папку** и скопируйте в неё `config.json` и `server.db` (папки `servers/` и `storage/` тоже, если они внутри проекта).
4. В новой папке выполните `npm install` (это обновит зависимости и `package-lock.json`; команду `npm ci` не используйте — в этой версии убраны ненужные пакеты `multer` и `mime-types`).
5. Запустите `npm start`. База обновляется сама: добавляются новые столбцы, ничего не удаляется. Существующие пользователи, приложения, задачи и профили остаются; роли «оператор» и «наблюдатель» сохраняют прежние права.
6. Обновите агентов на других компьютерах (раздел 8).

**Откат:** остановите панель и верните папку проекта вместе с `server.db` из копии, сделанной в шаге 2. (После первого запуска 2.0 в базе появляются новые столбцы — старой версии они не мешают, но надёжнее вернуть именно прежнюю копию базы.)

Что меняется для пользователей: старые токены (JWT в адресной строке) для скачивания больше не принимаются — скачивание идёт по одноразовым ссылкам. Если администратора когда-то переименовали, пользователь `admin` заново **не создаётся** (раньше создавался с известным паролем).

## 10. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Панель не открывается | в консоли панели нет ли ошибки порта («порт занят» — смените `port` или остановите другую программу); для доступа с другого компьютера нужен `"host": "0.0.0.0"` и разрешение в брандмауэре |
| `EACCES` / «порт 80» в Linux | используйте порт > 1024 или запускайте как службу из раздела 2 (там порт 80 выдаётся без root) |
| Вход: «Неверный логин или пароль» | пароль по умолчанию `admin`/`admin`; после 10–15 неверных попыток вход блокируется на 10 минут |
| «Нет доступа к этому серверу» | у пользователя не отмечен сервер (раздел 7) |
| «Недостаточно прав. Нужно разрешение: …» | попросите администратора выдать указанное право |
| Загрузка не начинается: «Недостаточно места» | освободите место; панель оставляет запас `minFreeDiskMb` |
| Загрузка обрывается на 1 МБ / ошибка 413 | в nginx слишком маленький `client_max_body_size` (см. раздел 4) |
| Загрузка обрывается через ~минуту простоя | прокси закрывает «молчащие» соединения — увеличьте его таймауты до 1200 с |
| «Файл слишком большой для файловой системы» | диск в FAT32 — используйте NTFS/exFAT/ext4 |
| Загрузка «зависла» после закрытия вкладки | откройте ту же папку и загрузите **тот же файл** ещё раз — загрузка продолжится с места остановки (хранится 48 часов) |
| Приложение не запускается | откройте его консоль/логи; на странице «Использовать проект» смотрите предупреждения (Java, EULA, `npm install`) |
| Minecraft: «Unsupported class file version» | нужна более новая Java — выберите её в настройках запуска (панель подсказывает версию) |
| Кнопки «назад/вперёд» мыши не работают | они работают через историю браузера; убедитесь, что браузер их поддерживает (Chrome, Edge, Firefox) |
| Консоль не обновляется | нужно право «Просмотр логов»; за прокси нужны заголовки WebSocket (см. пример nginx) |
| После обновления «белый экран» | обновите страницу с очисткой кэша (Ctrl+F5) |

Журнал действий пользователей — раздел «Журнал». Ошибки сервера — в консоли, где запущена панель (или `journalctl -u server-manager`).

## 11. Безопасность — на что обратить внимание

- Смените пароль `admin`, не открывайте панель в интернет без HTTPS.
- Запускайте панель от **отдельного пользователя без прав администратора/root**: все запущенные ею приложения получают его права. Файлы `config.json` и `server.db` недоступны через раздел «Файлы», но приложения, запущенные этим же пользователем, прочитать их могут — не давайте права «Создание приложений», «Редактирование файлов», «Консоль» людям, которым не доверяете как администраторам.
- В адресной строке больше не передаются токены входа: скачивание идёт по одноразовой ссылке, живущей 15 минут.
- Защита путей: нельзя выйти за пределы выбранной папки через `../`, абсолютные пути и символьные ссылки; закрыты `config.json`, `server.db` и служебные папки.
- Браузеру передаются защитные заголовки (`X-Frame-Options`, `nosniff`, `Content-Security-Policy`).
